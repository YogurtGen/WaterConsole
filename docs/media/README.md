# Documentation images

These images are generated by `scripts/capture-docs.mjs` from the actual WaterConsole React screens with **simulated documentation-only state**.

| File | View |
| --- | --- |
| `home.png` | Host Home and the Controller Lab library card. |
| `lobby.png` | PC pairing lobby with example connection details. |
| `phone-home.png` | Portrait phone navigation. |
| `phone-controller.png` | Landscape Controller Lab touch layout. |
| `controller-lab.png` | Host Controller Lab with four preview players. |
| `vibration.png` | Phone controller settings and vibration controls. |

Every image visibly says **Documentation preview**. Connection details use `example.invalid` and `PREVIEW`; they are not valid console credentials. The fixture does not discover or launch games and does not connect to a production session.

The browser vibration function is simulated for the settings screenshot. These captures demonstrate layout and available controls; they are **not** evidence of physical phone vibration, fullscreen/orientation support, LAN latency, or native-game compatibility.

To regenerate from the repository root after developer setup:

```powershell
node scripts/run-local.mjs scripts/capture-docs.mjs
```

Run `npm run build` first. The script uses installed Google Chrome by default; set `WATERCONSOLE_BROWSER=chromium` to use an installed Playwright Chromium fallback as described in [TESTING.md](../TESTING.md). It keeps generated files under this checkout; do not replace the fixture with a live session just to capture a QR. Inspect all screenshots before committing them.
