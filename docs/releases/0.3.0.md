# WaterConsole Core 0.3.0

## Added

- Add Game wizard for original Windows installations, metadata, player/display/connection labels, tags and managed local storage.
- Independent cover/banner uploads, non-destructive crop, destination-specific Recommended size, manual ratios, rotation and Fit/Fill previews.
- Controller Studio with four presets, custom modes, true analog, draggable D-pad, shapes, icons/text/images, role/player/PC-preview themes, grid/snap, alignment, grouping, undo and safe phone preview.
- Linked held actions and per-phone Classic/Assisted variants; separate per-player keyboard/gamepad bindings. The generic configured runtime coexists with source-built specialized adapters.
- Replayable spotlight tutorials for Add Game, crop and Studio: first-use guidance, Skip, Back/Next, keyboard dismissal and a ? replay button.
- Bundled v2 UserBridge, foreground/process validation, neutral recovery and optional slot-specific native rumble. No automatic driver installation. Only Controller Lab is bundled; no commercial integrations or media.

## Evidence

- TypeScript and production builds pass.
- 81 Core unit/integration tests pass, including concurrent persistence, backup recovery, held-source union, viewport bounds, profile authorization and the custom-input watchdog.
- 14 foundation Electron/browser checks pass; 12 editor GUI checks pass.
- 12 Studio integration checks pass on Core and the private build: actual separate XInput outputs, combined holds and analog axes reached an owned lightweight Windows fixture; release neutralized every device, and normal Stop waited for process exit. Directional D-pad bits were independent of analog; real keyboard combinations, focus reset, spectator state and synthetic per-slot rumble callbacks also passed.
- The separate private build's existing 99 unit tests pass. Its commercial adapters/art are not included in this release.

## Limits and remaining design targets

Browser controllers and vibration mocks do not establish four physical phones, Android fullscreen/physical vibration, prolonged Wi-Fi RTT, first-time usability or compatibility with a commercial game. Test your own game menus and gameplay separately. Authentication, launcher and anti-cheat requirements remain with each game.

The broader PRD retains design targets beyond this implementation: editable compact variants/anchors, custom viewport/safe-area simulation and detailed overlap/contrast diagnostics, saved color swatches/style clipboard, bounded tap behavior and fine content-placement/border-width controls. Current buttons are momentary holds; resizing/dragging/role colors and required shapes/content modes work. Arbitrary crowded layouts show an explicit fit fallback rather than silently clipping. Preset sharing/import/export, reusable user templates and advanced curves are future work.
